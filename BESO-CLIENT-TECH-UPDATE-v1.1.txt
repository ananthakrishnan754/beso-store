================================================================================
1. PROJECT ARCHITECTURE
================================================================================

BESO Store is a modern **headless e-commerce** architecture: the customer-facing
storefront is fully controlled by us, while Shopify remains the **system of
record** for catalog + commerce.

Frontend stack (verified in package.json / build):

  • Next.js 14 (App Router)
  • React 18 / React Server Components (RSC)
  • TypeScript strict
  • Tailwind CSS (custom semantic tokens, not stock class soup)
  • Three.js + @google/model-viewer (3D + AR)
  • Deployed to Vercel (auto-build from Git push)

Production URL:  https://beso-store-v2.vercel.app
Repo:            beso-store (GitHub) — every change is committed and deployed.

Backend-of-record:

  • Shopify  — products, variants, SKUs, prices, images, inventory, status,
               cart/checkout infrastructure, orders, fulfilment
  • Razorpay — planned payment provider (production Shopify store)
  • Zoho     — planned CRM / Inventory / Books (GST + accounting)

Architecture flow:

  Customer → Next.js Storefront → Next.js API layer → Shopify / Razorpay / Zoho

================================================================================
2. HEADLESS COMMERCE MODEL
================================================================================

We deliberately do NOT use Shopify's Liquid theme. Next.js renders 100% of the UI.

Shopify owns (via Admin GraphQL):
  products, variants, sku, price, compareAtPrice, images, inventoryPolicy,
  status (ACTIVE/DRAFT), metafields (namespace "beso": rating, reviews,
  subcategory)

Next.js owns: presentation, UX, theming, animation, comparison, SEO metadata,
and integration orchestration (auth, validation, credentials, error handling).

Why: this gives us full control over UX/performance/discovery and makes future
integrations (Razorpay, Zoho) a service-layer concern rather than a template
override.

================================================================================
3. NEXT.JS APP ARCHITECTURE
================================================================================

  • App Router with a hybrid Server/Client split.
  • React Server Components (RSC) fetch catalog data server-side — no API token
    ever ships to the browser.
  • Client components are used only for interactivity:
      - theme switching (ThemeSwitcher)
      - comparison tray + selection
      - "Explore 3D" model-viewer mount
      - mobile nav drawer
      - localStorage sync
      - animation/reveal triggers

Resilience model:

prices, rating metafields) — confirmed against the deployed Vercel build.

================================================================================
7. SHOPIFY CHECKOUT ARCHITECTURE (BUILT; READY FOR PAID STORE)
================================================================================

Endpoint:  POST /api/shopify-checkout  { sku, quantity }
Flow:
  SKU → resolve Shopify ProductVariant (Admin GraphQL, query "sku:")
       → cartCreate (Storefront GraphQL) → checkoutUrl → customer checkout

Security: variant resolution + cart creation happen server-side; browser never
sees Shopify credentials.

Status: variant resolution verified live (returns gid://.../ProductVariant/...).
Full checkout URL requires a Storefront API token + paid store (see §8).

================================================================================
8. DEVELOPMENT ACCOUNT LIMITATION (PLATFORM FACT, NOT ENGINEERING)
================================================================================

Shopify's free **Basic App Development** plan is password-walled and cannot
process real payments/checkout (payment + fulfilment APIs require merchant
approval). This is a Shopify licensing constraint, not a code gap.

Go-live prerequisites (documented in SHOPIFY.md):
  1. Client's paid Shopify store (or upgrade this one)
  2. Production Storefront API token
  3. Razorpay app install + set as primary payment provider
  4. Production domain
  5. Zoho credentials + API config
  6. Order webhooks → Inventory/Books connector
  7. Shiprocket/logistics config
  8. End-to-end order + payment testing

The frontend does NOT need to be rebuilt for this transition — only env values
and a re-run of the import against the client store:

  SHOPIFY_SHOP=<client-shop>.myshopify.com \
  SHOPIFY_TOKEN=<new-admin-token> node scripts/shopify-import.mjs
  ... node scripts/shopify-import.mjs --media --skus

================================================================================

19-21. THEME ENGINE
================================================================================

  • 10 theme configs (light/dark/mood) driven entirely by CSS custom properties
    (--app-rgb, --ink-rgb, --accent-rgb, --surface-*, --line-*, --glass …)
  • FOUC prevention: data-theme set in <head> before first paint
  • Default: Ivory Minimal (bg #F7F4EF, ink #1B1C1E, bronze #B38A4C, brand lime)
  • Serif display type, hairline rules, restrained accents — intentionally not
    "generic AI template"
